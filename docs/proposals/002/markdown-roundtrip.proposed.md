# Markdown round-trip rules (binding; read before changing or reviewing these paths)

Paths: `packages/core/src/parse.ts`, `format.ts`, `positions.ts`; `packages/editor/`; `packages/modes/`; `fixtures/markdown/`; `e2e/`. These rules bind as `CLAUDE.md`'s do and are named by its `## Read next`. They were moved here verbatim from `CLAUDE.md`'s `## Code rules` (DECISIONS #NNN); each keeps the DECISIONS id of the review that produced it. A lesson promoted for these paths is appended to the section it belongs to.

## Round-trip families

- Every round-trip family (parser ↔ serializer, mdast ↔ ProseMirror, the position map) has one corpus leg seeded from the writing surface's own output (a ProseMirror doc changed by a typing-shaped transaction, a mode operation's result), not only from parse(fixture); the test title names the leg, and the editor's output is asserted to be a fixed point of parse∘format.
- A corpus leg that claims to be seeded from the writing surface's own output includes at least one destructive transaction (a deletion, a split, a join), because the trees a parser cannot produce are usually reached by taking something away.
- A round-trip family's corpus legs seeded from the writing surface include one transaction that joins two blocks and one that deletes the whole separator between two inline nodes, and the family enumerates ordered pairs of the schema's mark kinds × the first run's edge-character class (punctuation, letter, astral), because a leg that edits one position inside one block never makes two nodes adjacent (DECISIONS #review-1-r9 O1).

## Serializer handlers, marks and delimiter runs

- A fix for a mark-edge or delimiter defect reads the serializer's handler for that mark before touching the editor's tree — both halves of every fixed-point family are owned, the tree the editor builds and the bytes the serializer writes for it — and every mark-edge guard is enumerated over both neighbour classes CommonMark §6.2 names (whitespace and punctuation) on every flanking mark (DECISIONS #review-1-r4 J1).
- An enumeration that mirrors a third-party rule derives its kind table from that rule's own branches, read in the installed package, never from the type list — a pair the table lacks is a pair the enumeration cannot fail on (DECISIONS #review-1-r4 J2).
- Every character classification in the app's serializer handlers is made in the parser's own terms — one UTF-16 unit, as `micromark-util-classify-character` reads it — and every character reference the app writes encodes a whole scalar (`codePointAt`), never a code unit; every neighbour-class enumeration carries one astral member (a non-BMP symbol and a non-BMP letter) beside its ASCII one, because a lone-surrogate reference decodes to U+FFFD silently (DECISIONS #review-1-r5 K1).
- A position map that instruments handler output learns every rewrite the parent makes after a handler returns, and its corpus case asserting that nothing is unresolved is the guard that names which rewrites exist — a new encoding in a handler is a change to that map (DECISIONS #review-1-r5 K2).
- An enumeration of rewrites that can each fire on one character includes the shortest value on which two of them fire on the same character — one scalar shared by two delimiter runs — and a neighbour-class enumeration includes the cell where one outside character is the closing neighbour of one run and the opening neighbour of the next (DECISIONS #review-1-r6 L1).
- A post-processor over a serializer's joined output is applied per child, over the slice the rewritten child occupies and at the positions the parent's rewrites touch, never over the join, and its guard set carries one member per node class whose bytes are literal — a code span, inline html, a link's destination and title — holding the exact bytes the post-processor matches (DECISIONS #review-1-r7 M1).
- When an enumeration of a parent's rewrites names a branch for a node class, the same guard asserts that branch's bytes on the parser's own tree — the node count after parse(format(·)) equal to the tree's — because a rewrite the map cannot follow is usually one the parser cannot read (DECISIONS #review-1-r7 M2).

## Position and cursor maps

- The cursor-map family asserts `toRendered(toSource(p)) === p` and the monotonicity of `toSource` over every text position of every fixture through the editor, seeded from parse(fixture) and from a destructive transaction, and every position class that is not the identity is a named guard on top of that leg, never a doc-comment rule (DECISIONS #review-1-r6 L3–L5).
- A two-view guard at a mark's end runs both routes — the input rule then the toggle, and a click then the toggle — and the toggle hands the editor's stored marks to the cursor map, because the editor inserts with `storedMarks ?? $pos.marks()` and a map that reads the doc alone proves one route only (DECISIONS #review-1-r7 M5).
- A cursor rule derived from the marks a typed character takes is applied at both edges of a block to every mark the schema declares — emphasis, strong, delete, link and inline code alike — placing the source caret outside each enclosing mark those marks do not carry and inside each they do, and its guard set enumerates every mark kind × both routes (stored marks cleared, inherited) × both edges × every textblock kind with an astral member, because a rule scoped to the node type that exposed it is one route and one kind short (DECISIONS #review-1-r8 N1).
- A correspondence between the editor's document and the tree the converter makes of it is anchored on the live document's own characters, never on widths read from the normalised tree, and its corpus leg deletes the first character of every textblock and asserts two-view insertion equivalence at every position of that block beside the inverse, because two directions built from one wrong offset table agree with each other while both are wrong (DECISIONS #review-1-r8 N2).
- A branch whose safety argument is that a second implementation enumerates the same cases is discharged by an instrument the corpus case reads — the branch records its give-up where the map reports `unresolved`, and a mutation that removes one case turns the corpus red — never by a doc-comment sentence, and the uncovered line in the coverage report is where that pair lives (DECISIONS #review-1-r8 N3).

## Caret placement in e2e

- An e2e places the rendered caret only through motions Blink alone decides — arrow keys (`ArrowUp`/`ArrowDown` reach a one-line block's edges on every OS, then counted `ArrowRight`/`ArrowLeft`) or a click at a computed point — never a Home/End key or a `ControlOrMeta+` chord in a contenteditable, because Cocoa resolves those before Blink sees them; a mark's text is asserted byte-exact with `textContent` and `toBe`, never a normalising matcher; a case whose bytes cannot tell two trees apart asserts the tree (DECISIONS #022).
