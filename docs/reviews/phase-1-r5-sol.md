## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

## Three riskiest things

1. Serializer correctness depends on parent-level rewriting after handlers return. A handler copied from a dependency inherits both that dependency's Unicode assumptions and a position-map instrumentation blind spot.
2. The live ProseMirror tree, normalized store tree and final serialized spelling can have different widths. Missing correspondence can leave most cursor tests green while a normal toggle targets the wrong character.
3. Source commit is deferred rather than cheap: isolated p95 56.5 ms here and 120.8 ms in accepted macOS CI. Phase 2 save/export/watch consumers must settle the burst and account for that blocking work.

## Class-level lessons (for docs/lessons.md)

- LESSON: Copying a third-party flanking table also copied its code-unit assumption, while the test table used only BMP neighbors → test supplementary scalars at both boundaries and assert preserved text through the real clipboard, not merely retained marks.
- LESSON: Instrumenting a child handler misses text rewritten by its parent after return → derive character correspondence from final spelling and test the complete edit → serialize → toggle → edit route.
- LESSON: A known expected failure remains a product defect when its discovery task lacks scope → disposition it at the named reconciliation by the user-visible consequence, and remove the exception when the fix lands.
