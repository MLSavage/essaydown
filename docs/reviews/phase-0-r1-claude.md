1. **should-fix** — `packages/core/src/sidecar.ts:1030` (`needsQuoting`) and `:1040` (`serializeScalar`) — `writeFrontMatter` accepts a replacement value containing `U+0000` or `U+2028`/`U+2029` and writes it raw into a plain or single-quoted scalar, reporting `ok: true`. `encodeDoubleQuoted` (`:921`) already escapes all of C0, DEL, C1 and lone surrogates, but `needsQuoting` — the predicate that decides whether a plain scalar must be promoted — tests only `[\n\r\t]`, `#`, `:` and the leading indicator, and the `quote === "'"` branch of `serializeScalar` escapes nothing but `'`. Reproduced: (a) `writeFrontMatter(root, {title: "a\u0000b"})` returns `ok: true`; the saved document then fails invariant A — `format(parse(format(w.root)))` is `---\ntitle: a\uFFFDb\n---…` against `---\ntitle: a\u0000b\n---…` — and the title reads back corrupted after reopen; (b) `writeFrontMatter(root, {title: "a\u2028b"})` returns `ok: true, changed: ["title"]`, yet `readFrontMatter(w.root).title` is already `null` and the block is `malformed`, because `KEY_LINE = /^([^\s#][^:]*):(?:[ \t](.*))?$/u` at `sidecar.ts:721` uses `.` with the `u` flag and no `s` flag, which does not match U+2028 — so the app writes a value into the user's front matter and then declares that block permanently read-only ("Edit this in the source view"), with every later `writeFrontMatter` returning `FrontMatterUnsupported`. ## Three riskiest things

1. **The front-matter writer is still the thinnest ice in `packages/core`.** 0.15 closed every hole r0 named and my 53-assertion probe found no regression in any of them — but I found two more in one pass, both from the same structural cause: `encodeDoubleQuoted` knows the full set of characters that cannot be written raw, and `needsQuoting` (plain) and the single-quote branch of `serializeScalar` each carry their own, smaller idea of that set. Three places encode one fact. Until the writer has exactly one predicate and the test asserts `readable(v) === !needsQuoting(v)` over a table that includes control characters, the next reviewer will find a third case. This lands on a user's real file the moment Phase 3 wires Outline's title/question editor.

2. **The runner's guards are now well written and unevenly tested.** The conformance suite is genuinely strong where it exists — it drives `ralph.sh run` and `gate.sh` for real and asserts that nothing was recorded on refusal, which is the right shape. But finding 2 shows the pattern: the fix task added the guard the finding named *and* a test for the two failure modes the task text listed, while the third branch — the one that encodes the finding's actual root cause — went in untested. Every `.g<n>`/`.r<k>` repair carries this risk, because the acceptance text is written from the finding and the finding is written from a symptom.

3. **`cargo test` and the Rust side are entirely unexercised, and the shell is the next thing built.** Phase 0 closes with 578 TypeScript tests, 71 runner tests, and zero Rust tests, while PRD §6.4's `WorkspaceRoot` path contract — canonicalisation, traversal, symlink, junction, case-fold — is the highest-consequence code in the product and lands in Phase 2. The three-OS green bar has proved nothing about Rust on any OS yet, and `apps/desktop/src/App.tsx` shipping a call to a command that no longer exists is a small early sign that the desktop app is the least-observed corner of the tree.

## Class-level lessons (for docs/lessons.md)

- LESSON: a hand-written serializer split its "what cannot be written raw" knowledge across three call sites (a full escape table in the quoted encoder, a short regex in the plain-scalar test, and nothing at all in the single-quoted branch), so the reader accepted a value the writer could only damage → derive every quoting decision from one predicate that the encoder itself owns, and assert the inverse property (`readable(v) === !needsQuoting(v)`) over a value table that includes C0, DEL, C1, U+2028/U+2029 and lone surrogates, not only printable strings.
- LESSON: a regex written with the `u` flag and no `s` flag silently stops matching a line the moment that line contains U+2028 or U+2029, because `.` excludes them as line terminators, so a line-oriented parser can classify its own output as malformed → when a "line" is defined by splitting on `\n`, match its contents with an explicit character class rather than `.`, and probe the parser with every code point the language calls a line terminator.
- LESSON: a fix task's acceptance is written from the finding's symptom, so the guard that closes the finding's *cause* can ship untested while the suite goes green on the two symptoms the text listed → when a fix adds several guards, enumerate the guards from the diff and require one conformance leg per guard, not one per sentence of the acceptance.
- LESSON: a rule promoted into CLAUDE.md named three no-op arguments and the tree implemented two, and nothing checks the promotion against the code → a `promote-lessons` step should end by naming, in the journal, which test discharges each clause of the promoted rule, so a rule the tree does not yet satisfy is visible at the moment it is written down rather than at the next review.
- LESSON: removing a command from the Rust IPC surface left a UI that still invokes it, and every acceptance check (window title, lint, typecheck, tests) stayed green because none of them clicks anything → when a task removes an IPC command, grep the frontend for its name in the same task and either fix the caller or write the breakage into the deferral note, because a backlog line written before the removal describes a page that no longer exists.
