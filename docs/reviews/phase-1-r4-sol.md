## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **blocker** — **packages/editor/src/schema.ts:1210; packages/core/src/format.ts:68** — Deleting the space after a strikethrough run ending in a link makes Copy Markdown emit non-round-tripping bytes and silently lose the strikethrough in the copied document. Reproduction: load `~~a [b ](u)~~ c` plus LF, click the paragraph (asserted text anchor `" c"`, offset 2), ArrowLeft (asserted offset 1), Backspace, Copy Markdown. The real clipboard is `~~a [b ](u)~~c\n`; parsing produces literal tildes around a link, with no `delete` node, and formatting returns `\~\~a [b ](u)\~\~c\n`. The rendered DOM still has `<del>` elements and the status says `Copied Markdown` (/report/strike-probe.log). The link's closing punctuation followed by an alphanumeric character changes the closing delimiter's flanking context; checking only whitespace inside the mark does not cover it. Fix: make strikethrough serialization protect both delimiter boundaries using the actual neighboring characters, including link/image punctuation and text outside the mark; apply the formatter's context-sensitive escaping approach so reparsing preserves the delete/link tree without moving the link's whitespace or dropping the mark. Add the real deletion-and-copy regression and corpus edits immediately outside every marked run, with both fixed-point and parsed mark/link assertions and presence/absence cases for punctuation versus letters.

2. **should-fix — Required** — **packages/editor/src/toggle.ts:351** — A rendered cursor after content removed by normalization maps to the containing block's start, so toggling and continuing to type inserts at the wrong end of the paragraph. Browser reproduction in /report/cursor-probe.log: load `abc` + hard break + `def`, click the end (asserted `def`, offset 3), Backspace three times, toggle to source, type `X`; the pane becomes `Xabc\n`, not `abcX\n`. `innermostAt` falls back to the block correspondence and the no-spelling branch returns its start. Task 1.37 already identifies this and the split-list empty-paragraph sibling, but its test-only scope is the sole stated reason for deferring the fix; Backspace and source toggle are existing Phase 1 actions. Fix: when a live position is beyond the last surviving inline correspondence or inside a dropped placeholder, map to the nearest preceding serialized content's end, including nested list items, while retaining the existing atom/start behavior. Fold both known-defect collections into ordinary passing corpus assertions, remove the `it.fails` case, and add the browser deletion → toggle → type regression with its caret precondition.

## Three riskiest things

1. Delimiter validity depends on characters outside the marked run as well as its internal whitespace. Editing beside a mark can invalidate serialization while every inside-the-mark leg passes.
2. The live editor and normalized store have different widths after deletion. Mapping an enclosing node is insufficient to preserve the caret; the expected-failure test currently certifies that this remains broken.
3. Source commits retain a separate pending buffer and take tens of milliseconds. Phase 2 readers must settle it before save/export/history reads; the existing clipboard and toggle checks do not discharge future consumers.

## Class-level lessons (for docs/lessons.md)

- LESSON: Normalizing a mark's interior misses flanking changes caused by deleting its neighbor → enumerate edits immediately before and after each mark and assert the parsed mark tree beside the fixed point.
- LESSON: A test-only task can discover a defect outside its edit scope but still inside the current phase's user path → record the discovery immediately, then let reconciliation schedule the product fix before close rather than equating task scope with acceptable deferral.
- LESSON: Normalization can remove live editor positions while retaining their enclosing block → map unmatched positions to the nearest surviving content boundary and test the next typed character after a toggle.
