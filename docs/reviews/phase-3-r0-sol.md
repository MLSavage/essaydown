## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **blocker** — apps/desktop/src/workspace/DocumentPane.tsx:285; apps/desktop/src/workspace/document-sync.ts:292 — An external-file event silently replaces a pending source edit because the watcher decides the document is clean before settling CodeMirror. Reproduction: open `Alpha.`, toggle to source, type `LOCAL`, then deliver an external append within the source coalescing window. After the 100 ms watcher debounce, both the source buffer and store contain only the external version; `LOCAL` is gone, no conflict or error appears, and it remains gone after 1.3 s (/report/browser-probes.log:1–15). The source binding's eventual cleanup flushes an obsolete store, not the replacement the user sees. Fix: settle pending source input before the watcher makes its clean/dirty adoption decision, including edits arriving during its awaited disk read. Test both timing positions through the pane and assert local text survives behind the conflict banner; exercise Keep mine inside the source window as another store reader.

2. **blocker** — packages/core/src/sidecar.ts:582 and :631 — Reorder/Outline permutations apply to stale anchor positions after ordinary typing, permanently assigning variants/questions to the wrong logical item. The editor changes the root without refreshing the sidecar; Rewrite's display resolves anchors, but `applyReorderSentences` and `carryTopLevelMove` pass the unresolved sidecar to positional `reanchor`. Reproduction: attach a variant to `Beta here.` in `Alpha here. Beta here.`, insert `New first.` before them, then reorder `[0,2,1]`. Before the move the displayed variant correctly belongs to Beta; afterward it belongs to Alpha. Inserting an introductory paragraph then moving Beta before Alpha reproduces the same reassignment through `applyMoveBlock` (/report/core-probes.log:1–33). Refreshing on disk does not repair an anchor whose hash/text have already been rebuilt for the wrong sentence. Fix: resolve every active anchor against the pre-move root before applying the permutation, preserving unresolved entries as orphans. Guard sentence, paragraph and section/Outline moves after typing that shifts indices, plus duplicate identities, undo and save/reload.

3. **blocker** — apps/desktop/src/workspace/DocumentPane.tsx:249 — A skipped sidecar write resolves successfully, allowing close/switch/rename to discard variants or questions that never reached disk. With an externally malformed sidecar (`{broken`) and one newly added variant, `pane.flush()` returns `saved`, leaves the malformed disk bytes untouched, and retains the variant only in memory (/report/browser-probes.log:16–23). A parse error is reported, but the checked save outcome still authorizes discarding that memory. Fix: make the skip branch fail through the existing `MarkdownWritten` path (throw the choice error inside its surrounding try), retaining the successful Markdown baseline while keeping the document dirty. Test that flush returns `failed`, destructive callers stay on the document, and a repaired sidecar permits a later successful save retaining the variant.

4. **should-fix Required** — apps/desktop/src/rewrite/RewritePanel.tsx:102; apps/desktop/src/reorder/ReorderPanel.tsx:97 — Both panels interpret a live ProseMirror cursor using a reconstructed, normalized document whose positions differ. In `Alpha.` / `Beta.`, insert an empty paragraph before Alpha and leave the caret at Alpha's end. The live document has `['', 'Alpha.', 'Beta.']`, cursor 9; the reconstructed document has no empty paragraph, so Rewrite displays Beta's card (/report/browser-probes.log:24–31). Reorder uses the same invalid correspondence. This is the rendered surface, not #054's accepted source-caret cut. Fix: derive the semantic block/sentence focus from the live editor document and carry a correspondence to the store root that accounts for omitted blocks and trimmed characters. Guard empty paragraphs and whitespace-only blocks at the beginning/middle/end, and leading/trailing whitespace; assert each panel targets the actual caret paragraph after destructive edits.

5. **should-fix Required** — apps/desktop/src/outline/OutlinePanel.tsx:28; apps/desktop/src/outline/OutlineTree.tsx:37 — Outline has no store Undo/Redo keyboard handler outside the editor, so its own action button/drag handle cannot undo the action just performed. Add `Why now?`, click New question, then press Ctrl+Z with that button still focused: the heading remains (/report/browser-probes.log:32–40). Rewrite and Reorder install `useStoreUndoKeys`; Outline does not, and App supplies no equivalent. Fix: install the store history routing once for Outline or at the common mode owner, preserving text-field native undo and preventing double dispatch. Test Undo and Redo immediately after New question and a tree drop without refocusing the editor, asserting both Markdown and sidecar restoration.

## Three riskiest things

1. Source buffering and file synchronization have separate notions of “dirty.” The existing switch/toggle tests settle explicitly, leaving watcher-driven replacement outside their coverage.
2. Anchor resolution and permutation are composed inconsistently: a correct sidebar display can conceal stale stored positions until a drag converts them into incorrect hashes and text.
3. Successful Markdown I/O is still conflated with successful document persistence on the sidecar-skip branch; the save barrier can authorize losing metadata despite emitting an error.

## Class-level lessons (for docs/lessons.md)

- LESSON: Introducing a deferred editing buffer creates dirty state outside the document store → test every external adoption and discard decision with input arriving both before and during awaited reads.
- LESSON: Display-time anchor resolution does not make stored positional metadata current → resolve against the old tree before applying a permutation, then test typing followed by moving and reloading.
- LESSON: A normalized tree cannot interpret positions from the live editing tree → carry an explicit live-to-stored correspondence and include empty/trimmed blocks in panel-targeting tests.
- LESSON: Reporting an error while resolving a save successfully violates the caller's discard contract → propagate partial persistence as a checked failure and test the complete document, including sidecar-only edits.
- LESSON: Proving an undo snapshot exists does not prove users can reach it → send Undo from the exact element that retains focus after each mode action.
