## Three riskiest things

1. The gate's export evidence validates argument lists the product never sends (finding 1). Every future export gate inherits this unless the test asserts that its invocation equals `buildPandocArgs` exactly. An EPUB that Apple Books or a store rejects would reach the user as a successful export.
2. The app's own export route (sidecar resolution, PATH prepend, cwd-relative media extraction) is exercised only on an image-less PDF (finding 2). The class that broke in 4.17 is unguarded on all three OSes, and Phase 6 packaging (a new bundle layout per OS) is exactly where it would recur.
3. §6.2 anchoring still shifts to the wrong twin on two in-app routes (findings 3 and 4). Both are disclosed in backlog 202, but (b) is now reproduced, and both silently attach the user's rewrite history to the wrong sentence.

## Class-level lessons (for docs/lessons.md)

- LESSON: a validator leg made green by adding arguments the product never sends (`--metadata title=`, `lang=`) turns the gate into a test of the test → a gate's export invocation is the product's argument builder's own output, asserted equal in the test; any gap goes into the product or into a DECISIONS entry naming the invalid artifact the user gets.
- LESSON: a fix that carries state through one editing surface (rendered view) leaves the other (source view) on the old behaviour, and a residual "read, not run" in the backlog stays unreproduced → a fix to a cross-surface invariant runs its reproduction through every surface that commits to the store, or names each excluded surface as a test that asserts the old behaviour.
- LESSON: a capability scope that "validates paths" while the plugin also accepts `cwd`/`env` validates nothing about location → grant no webview capability the frontend does not call, and check a scope against every field of the plugin's command input, not only `args`.
