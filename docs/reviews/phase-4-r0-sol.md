## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **blocker** — `apps/desktop/src-tauri/src/export.rs:90`, `packages/export/test/integration.test.ts:238`, `.github/workflows/ci.yml:195` — The application does not produce the HTML/EPUB files that the gate validates: tests and CI supply missing metadata only to their own invocations. `/report/validate_exports.py` runs the application's nine-token shape against the fixture: HTML fails for absent `lang`; EPUB lacks `dc:title` and has an empty navigation anchor even under `LANG=en_US.UTF-8`. Pandoc exits 0, so the application reports success. The title failure is independent of the explicitly deferred C-locale issue in #065. Fix: supply a nonempty title through the production export path, using the existing document title or a filename fallback, and make the validator tests consume production arguments without test-only title injection. Reconcile the HTML-language requirement with #065's retained invocation explicitly: provide the agreed production language source or amend that acceptance as a deliberate exception. Do not claim the current gate passes from augmented test output.

2. **blocker** — `packages/core/src/sidecar.ts:783` — Live anchor carrying maps only the containing block and then chooses the duplicate nearest the old sentence index, so inserting a duplicate within that block attaches a rewrite to the wrong sentence. `/report/anchor-probe.ts` binds the real ProseMirror store to `Same line here. Same line here.`, anchors the second sentence, then types `Same line here. ` at the paragraph start one character per transaction. After Markdown/sidecar serialization and reload, the rewrite resolves to occurrence 1 at `[0,1]`; its original sentence is occurrence 2 at `[0,2]` (`/report/anchor-probe.log`). This is an in-app edit with available transaction mapping, outside §6.2's external-edit ambiguity. Fix: carry the anchored sentence's own mapped character range through the transaction rather than choosing by its old index within a mapped block; add this reproduction and corpus guards for same-block duplicate insertion/deletion alongside the existing separate-paragraph case.

3. **blocker** — `apps/desktop/src-tauri/src/commands.rs:231`, `apps/desktop/src-tauri/src/export.rs:99` — The custom export IPC passes an unvalidated `format` directly to pandoc, allowing a Lua writer pathname to bypass the shell capability's writer restriction and workspace authority. `ShellExt::sidecar` does not apply the webview shell scope (also documented in `shell_scope.rs:6`). The TS format validator protects the dialog only. The production-shaped invocation with `-t /report/probe-writer.lua` exits 0 and executes that file, writing `/report/lua-writer-executed.txt`; the source/output path checks never examine the writer path. This demonstrates the argv consequence; no live-webview exploit was run. Fix: enforce the writer-name grammar in the Rust command before spawning, with a typed rejection; test through the custom `export` IPC that absolute/relative Lua paths and malformed writer values cannot execute, alongside accepted ordinary formats. The existing `plugin:shell|spawn` tests do not discharge this route.

4. **blocker** — `packages/export/src/index.ts:40`, `apps/desktop/src/workspace/ExportDialog.tsx:115` — HTML exported to another allowed directory silently loses relative images because `--resource-path` resolves input resources but does not rebase HTML `src` values to the output location. Reproduction: workspace `docs/essay.md` contains `![](assets/pic.png)` and the image exists; select HTML and output `out/essay.html`. Exact arguments leave `<img src="assets/pic.png">`, pointing at nonexistent `out/assets/pic.png`, with no warning and exit 0 (`/report/html-relocation.log`, generated file under `/report/html-relocation/out/`). Fix: rebase local HTML resource URLs from document directory to output directory, or embed/copy the resources as an explicitly chosen export policy. Add a relocated-output case that resolves the emitted URLs and checks image bytes, including a nested path with spaces.

5. **should-fix Required** — `apps/desktop/src-tauri/src/export.rs:28`, `apps/desktop/src/workspace/export-sync.ts:57` — Every successful export loses the reveal path at the Rust/TypeScript boundary: serde emits `out_path`, while the frontend reads `outPath`. No serde rename or adapter exists. `/report/reveal-probe.log` feeds the actual serialized field spelling to `exportDocument`; it calls reveal with `undefined`, suppresses the error, and returns `exported`. The fake responses in `tests/export-sync.test.ts:35` all use camelCase, hiding the mismatch. Fix: use one wire spelling (for example serde `rename_all = "camelCase"`) and assert the full serialized response in Rust plus its consumption by the frontend; verify reveal receives the actual output path.

## Three riskiest things

1. Validator evidence is detached from application behavior: test-only metadata, a PDF-only UI export case, and no check that emitted HTML resources resolve leave successful-looking exports unverified.
2. Live identity is reduced to block correspondence plus sentence rank; same-block edits can move saved rewrites onto another item while parse/format and reload remain internally consistent.
3. Security and response contracts cross two independently implemented boundaries: shell capability tests exercise a different spawn route, and typed frontend mocks do not validate Rust's actual JSON.

## Class-level lessons (for docs/lessons.md)

- LESSON: a validator passes only after its test adds arguments absent from production → validate the exact application invocation and record intentional exceptions separately from a passing product gate.
- LESSON: mapping an item's container and reusing its old rank loses identity when duplicates are inserted inside that container → map the item's own range and test duplicate edits both within and across containers.
- LESSON: capability validation on one IPC route does not constrain a custom Rust spawn route → test rejected arguments through the command the product actually exposes.
- LESSON: independently typed mocks agree on a field name the real serializer never emits → test serialized backend payloads at the frontend boundary.
- LESSON: locating an input image does not prove its URL remains valid in an exported document → resolve resources from the output document's location in relocation guards.
