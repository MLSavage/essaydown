## Three riskiest things

1. **`&#x20;` was treated as one defect and it is a family.** The r0 blocker was "a trailing space before Enter"; 1.13 fixed the block's two ends, and the corpus leg it added types a space at every block end — the same shape as the fix. Two other members of the family survive at this SHA (finding 2, after a hard break; and `emphasis[text("b ")]` → `a *b&#x20;*&#x20;c`, unreachable today only because Phase 1 binds no mark-toggle command and will be reachable the moment Phase 3 does). The general statement is: any mdast tree the editor can build that `parse` cannot produce makes the serializer emit bytes no Markdown file contains. Nothing in the suite enumerates those trees; the corpus leg samples one shape of them. Phase 2 puts this string on disk.

2. **The phase's defects cluster in the one directory with no unit coverage.** `apps/desktop/src/dev/` holds the wiring — store, bindings, cursor carry, flush, copy — and is excluded from coverage by `vitest.config.ts:14`. r0 found two defects there, this review found the blocker there. Phase 2 moves exactly this wiring into the shell, where the same seam becomes autosave and the file tree. The coverage number will keep rising while the risk concentrates in the part it does not measure.

3. **The latency work moved cost off the keystroke without bounding where it went.** 1.17's source-view fix defers a whole-buffer `parse` to the burst boundary. That deferral is what makes the copy button wrong (finding 1) and what makes the source `pane` metric report `n=0` (finding 6), and the deferred cost itself is measured nowhere. Every future consumer of the store — autosave, the watcher, the sidecar writer, Phase 3's modes — will read a root that can be up to one coalescing window behind the buffer, and only `toggle` and `destroy` currently know to flush. The next component that reads the store without flushing repeats finding 1 exactly.

## Class-level lessons (for docs/lessons.md)

- LESSON: a fix that strips whitespace "at the block's two ends" closes the shape the reporter hit and leaves every other boundary in the same family open — an interior atom (`break`), a mark edge, a table-cell edge each have two sides and the parser treats them asymmetrically → enumerate the boundaries the *parser* normalises (from micromark's rules, not from the bug report) and give each one a guard that asserts the serialised bytes, not only the tree; a guard that asserts the tree while the sibling guards assert `format` is the one that will pin a defect as correct.
- LESSON: making a write deferred turns every existing reader of that store into a potential stale-read site, and the fix task's acceptance will only enumerate the readers it happens to know (toggle, unmount) → when a commit becomes asynchronous, enumerate its readers from the codebase (`grep` for the store getter) rather than from the task text, and either flush in the accessor or make the pending state visible so a reader cannot ignore it.
- LESSON: a coverage `include` glob that names the pure packages and omits the app wiring reports a rising number about the half that was already at ceiling, while the defects land in the half it cannot see → keep the excluded paths in the config as an explicit list with a comment naming the suite that covers them instead, so "not measured" is a decision in the file rather than an absence.
- LESSON: a defect discovered while fixing another one gets written into `docs/lessons.md` and an e2e comment, which are read by people and not by the graph → a defect that is not being fixed now needs a `docs/V1.1-BACKLOG.md` line with a revisit trigger and a hard stop, or the next reconciliation has no way to know it exists.
