## Findings (≤ 20, most severe first)

1. **blocker** — `packages/editor/src/schema.ts:674` (`stripUnparsableWhitespace`, and the ownership rule in its doc comment at `:640-670`) — a `hard_break` sitting at a block's **end** is left in place, and `format` writes it as a bare trailing `\` that `parse` reads back as a literal backslash, so Copy Markdown puts non-round-tripping bytes on the clipboard and reports "Copied Markdown". Reproduced in Chromium at this SHA: seed `one\`+LF+`two` through the source view, `Ctrl+End`, three `Backspace` presses — the pane shows `"one\\\n"`, and an init-script `writeText` spy records exactly `["one\\\n"]` while `[data-testid=status]` reads `Copied Markdown`. `format(parse("one\\\n"))` is `"one\\\\\n"`, and the reparsed paragraph's only child is `{type:"text",value:"one\\"}` — the `break` node is gone, replaced by a backslash character a third-party reader renders visibly. This is the r0 F1 / r1 G4 family (a tree the editor can build that `parse` cannot produce), and the r1 reconciliation recorded exactly that general statement as Claude's risk 1; task 1.25's boundary enumeration covers whitespace at every boundary but never an **atom** at a block end, so `editor-fixed-point.test.ts`'s eleven boundary guards and both corpus legs miss it — the legs only ever `insertText` (`packages/editor/test/typing-legs.ts:48,104`), never delete, and a trailing `break` is not producible by `parse`, so the corpus is closed against it. Fix: extend the ownership rule to atoms at a block end — drop a trailing `hard_break` from the node list in `stripUnparsableWhitespace` (a break with nothing after it is not a line break; CommonMark §6.7 requires a following line), the same way a run trimmed to nothing is dropped, and add a boundary guard per position (a break as the block's last node, a block that is only a break) asserting `format(root)` bytes and `format(parse(format(root))) === format(root)`, plus one browser case that deletes rather than types.

2. **should-fix** — `apps/desktop/src/dev/DevEditor.tsx:102` — the flush that `toggle` performs before reading the store has no test that fails without it: replacing that line with a comment leaves the full `e2e/web` suite **68/68 green** (and every vitest suite green by construction, since `apps/desktop/src/**` is outside the coverage glob and has no unit tests). `toggle` is the first reader named by the rule this phase promoted into CLAUDE.md — "every reader of the document store that is not an editing surface (copy, undo/redo, toggle, unmount, save, export) settles the pending source burst before it reads, and a new reader's test is an action inside the coalescing window" — and it is the one reader of the four that has no such case. My probes could not find a behavioural difference either (text, caret and undo depth were identical with and without the line), which points at the line being redundant with `SourceBinding.destroy`'s own flush on the mode-change effect cleanup, while its comment at `:98-101` asserts an ordering it is no longer the cause of. ## Three riskiest things

1. **The `&#x20;` family is still being found one member at a time, three review attempts running.** r0 found the typed trailing space, r1 found the space after a hard break and both sides of a soft break, and this attempt found the atom itself at a block end. Each fix enumerated the boundaries of the *previous* symptom — whitespace — while the invariant that actually matters is the one r1 recorded as a risk and did not turn into a task: *every tree the editor can build that `parse` cannot produce makes the serializer emit bytes no Markdown file contains.* Until something enumerates the editor-reachable trees rather than the reported reproductions — a corpus leg seeded from **deletions and structural edits**, not only `insertText` — the next attempt will find the next member. `pmToMdast`'s output being in the image of `parse` is a property that can be asserted directly on every fixture after an arbitrary editing transaction; nothing asserts it today.
2. **`apps/desktop/src/**` is measured by nothing but Playwright, and Playwright's coverage of it is thinner than it looks.** Findings 2 and 3 are both in `DevEditor.tsx`: one flush that no test can fail without, and a control whose only click in the entire suite goes to a stub. r0's F3/F4 and r1's G1 also landed in this file. It is the file the gate criterion is written about, it has 0 % measured coverage, and Phase 2 moves exactly this wiring into the shell — so the backlog's "decide the include at Phase 2 planning" is carrying more weight than a deferred nit usually does.
3. **The one thing this container cannot check is the one thing that failed last round.** The Windows Playwright leg is green at `1.verify.r2.g1h`, but 1.28 achieved that by removing the assertion that touched the OS — which is the right fix for the CRLF problem and also means the windows-latest leg no longer proves anything about the clipboard beyond the app's own `writeText` argument. Combined with finding 3, the product's actual copy path on Windows is now attested by nothing but the r2h run that failed. Michael's manual gate is the only remaining evidence that Copy Markdown works on a real machine.

## Class-level lessons (for docs/lessons.md)

- LESSON: three attempts running, a fix task enumerated the boundaries of the *symptom* that was reported (whitespace at a soft break, whitespace after a hard break) while the defect class was "a tree the editor can build that the parser cannot produce", so the next member of the family was found by the next review instead of by the fix → when a finding is one instance of a stated invariant, the fix task asserts the invariant over the corpus (here: `pmToMdast` output is in the image of `parse`, after an arbitrary editing transaction including deletions), and enumerates instances only as named guards on top of it.
- LESSON: a corpus round-trip leg seeded only from `insertText` cannot reach any tree that requires a deletion to build, so a paragraph ending in a hard break — one `Backspace` sequence away from a fixture in the index — was outside every one of the eleven boundary guards and both corpus legs → a round-trip leg that claims to be seeded from the writing surface's own output includes at least one destructive transaction (delete a range, split and rejoin a block), because the trees a parser cannot produce are usually reached by taking something away, not by adding a character.
- LESSON: replacing a browser assertion that read a shared OS resource with an in-page spy fixed the platform-dependence and silently deleted the suite's last end-to-end evidence that the control works at all — the same helper was the only caller, so removing the real path from it removed it from everywhere → when a spy replaces a real resource in a helper, count the callers of that helper first, and keep one non-spy case asserting the weakest platform-independent property (the promise resolves, the status changes) so the real path stays attested.
- LESSON: a procedure change promoted into `CLAUDE.md`/`AGENTS.md` by a `verify` task was not carried into `ralph/PROMPT.md`, the generated wrapper each task actually reads first, so the very next task stopped on the contradiction and spent one of its three attempts on it → a rule promoted into the agent files names, in the same commit, every other file that restates the same procedure, and the equality check that guards them (`ralph/check-agent-rules.sh`, `tests/agent-rules.test.ts`) is widened to cover the wrapper.
