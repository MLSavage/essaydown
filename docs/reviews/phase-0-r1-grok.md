The function's own comment at L1060-1061 (“a key whose value is already what is asked for is not rewritten at all”) is false for this shape, and the promoted CLAUDE.md/AGENTS.md identity rule (L39: “an unchanged front-matter value re-serialises byte-identically for every fixture in fixtures/markdown/index.json”) has no corpus loop — only sentence reorder/replace in `sentences-zero-width.test.ts:205-274`. ## Three riskiest things

1. `writeFrontMatter` no-op refuse on a decoded `\n` (finding 1). Phase 1's save path will call this with the sidecar's mirrored `topicQuestion`; a document whose `question:` is a supported double-quoted escape of a newline becomes an in-app save error even when the user changed nothing. The returned `root` is identity, so a caller that always persists `write.root` is safe; a caller that treats `ok: false` as abort of the whole save is not.

2. F14, still deferred (`docs/V1.1-BACKLOG.md`): `withLock` is released before the iteration (`ralph/lib/run.mjs:101` then the loop body). The lock's contract is state and ref mutation; a second operator-started `ralph.sh run` can still enter the same worktree. Manual procedure in DECISIONS #review-0-r0 stands.

3. `cargo test` is still 0/0/0 on all three OS. Phase 2 is the first real Rust evidence (F21). A regressing `lib.rs` that still compiles will look green.

## Class-level lessons (for docs/lessons.md)

- LESSON: a guard that runs before the identity skip makes the skip dead for every value the guard rejects → put “already this value → no write” first, then refuse the illegal *change*.
- LESSON: promoting “identity of f(root, no-op) over the corpus” as a code rule does not create the test; name each no-op (permutation, self-replace, unchanged front-matter) in the verifier task that is supposed to carry it, or the third one is prose.
- LESSON: a conformance test that covers “missing file” and “digest mismatch” can still miss the third consumer clause (manifest `sha` ≠ recorded SHA) → one fixture per predicate the production `if` actually has.
