## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **blocker** — `packages/core/src/format.ts:193` — The surrogate repair misses one astral character whose two halves are both encoded because it lies between two flanking runs. `containerPhrasing` first writes the high-surrogate reference after the left mark, then the low-surrogate reference before the right mark; `SPLIT_PAIR` accepts only a reference beside a *raw* surrogate. `format(parse('*a.*&#x1F600;*(b)*'))` writes `*a.*&#xD83D;&#xDE00;*(b)*\n`, reparsing to `a.��(b)` and leaving map path `0.1` unresolved. `/report/between-browser.mjs` reproduces through ordinary caret motion and two deletions: load `*a.* 😀 *(b)*`, remove the spaces around the emoji, Copy Markdown; the rendered text still contains 😀 and the status reports success, while the clipboard holds the corrupt form. U+10400 behaves identically; the extended probe covers all nine pairs of emphasis/strong/delete and embedded contexts. The existing “both sides at once” test at `strikethrough-flanking.test.ts:394` puts two different emoji around one mark, so never composes both rewrites on one scalar. Fix: widen the adjacent high-reference + low-reference form to one scalar reference as well, retaining parser-side UTF-16 classification; add mark-pair × non-BMP symbol/letter guards and a corpus fixture with one scalar between two runs. Assert parsed text equality, fixed point, empty `unresolved`, spelling positions, and the real delete/copy route.

2. **should-fix — Required** — `packages/core/src/positions.ts:540` — Emission placement still ignores the serializer's newline-to-space rewrite immediately before inline HTML, so toggling moves a caret in the preceding text to its start. This is independent of finding 1 and of surrogate encoding. Installed `mdast-util-to-markdown/lib/util/container-phrasing.js` replaces the previous result's final EOL with a space when the next child is `html`; the “no other rewrite” claim at `positions.ts:560` is false. `formatWithMap(parse('alpha\n<i>beta</i>'))` leaves `0.0` unresolved. `/report/html-map-browser.log` asserts the rendered caret at `{text:'alpha\n', offset:5}`, then toggles and types `X`; the clipboard is `Xalpha <i>beta</i>\n`, instead of `alphaX <i>beta</i>\n`. The `<span>` twin, linked form and a non-BMP soft-break seed also fail placement. Fix: account for this parent rewrite in emission placement **and** the text spelling table, preserving offsets before/after the rewritten LF and the opaque HTML bytes. Add parser-seeded and destructive editor-seeded corpus cases plus a toggle/type browser guard; assert expected character positions, not monotonicity alone.

3. **should-fix — Required** — `e2e/web/editor-soft-line-breaks.spec.ts:130` — The counted-arrow G4 setup intermittently lands at offset 6 instead of 5, preventing the gate from exercising its whitespace assertion. `/report/e2e.log` reproduces exactly r6h a1's Windows failure (`workflow.log:6413`): the anchor at offset 16 passes, but after eleven ArrowLeft presses the final location check times out at 6. ## Three riskiest things

1. Two individually tested serializer rewrites can act on the same character. Branch coverage and one-mark “both sides” tests do not exercise that composition; the remaining case silently corrupts the clipboard.
2. The position map assumes it knows every parent rewrite. An unlisted HTML-adjacency rewrite leaves an entire text node unresolved, and nondecreasing-but-constant cursor answers conceal the wrong edit location.
3. A green accepted rerun can coexist with a repeatable class of test-setup failures. The actual a1 failure and independent recurrence must inform the disposition before the next phase relies on this gate.

## Class-level lessons (for docs/lessons.md)

- LESSON: Enumerating each rewrite independently misses their composition on one minimal input → test the shortest value on which both transformations can fire, including one scalar shared by two delimiter runs.
- LESSON: A comment claiming a complete parent-rewrite list was derived only from the defect's two branches → inspect every assignment to accumulated child output, including unrelated node-type branches, and test both byte placement and semantic cursor position.
- LESSON: Monotonicity accepts a constant wrong cursor map → pair it with independently expected character positions and a toggle followed by typing.
- LESSON: An assertion timeout before the final content check can still be a reproducible test defect → retain failed-attempt evidence and repair recurring setup failures instead of treating a passing rerun as a diagnosis.
