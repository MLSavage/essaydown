## Findings (≤ 20, most severe first)

1. **nit** — `packages/editor/test/position-map-editor-leg.test.ts:180` — `expect(names.length).toBe(Object.keys(index).length)` is `x === x`: `names` is `Object.keys(index).sort()` (`:52`). The real guards are `blockEndChecked` / `inBlockChecked` equal to `names` (`:249-250`). Same class as F9(c) / G8, which 1.21 and 1.26 removed from the neighbouring files. Fix: drop the length assertion, or collect the names the `for` loop actually constructed the `it` titles from and compare that list to `names`.

2. **nit** — `ralph/` per-task `PROMPT.md` generation — 1.verify.r2 wrote the stub-first `## Every iteration` list into `CLAUDE.md`/`AGENTS.md` (`6d9345c`); the generated wrapper handed to `1.verify.r2.g1` still said implement-then-one-journal-entry, and attempt 1 stopped (`journal-main.md` 2026-09-10T16:53:30Z) rather than choose. Attempt 2 applied CLAUDE.md's stated precedence and the gate ran. The product criterion is not in question. Fix: the generator that emits `PROMPT.md` copies the current `## Every iteration` list from `CLAUDE.md` (or the template is updated in the same commit that changes that list), so a later task in the same chain is not handed a wrapper that contradicts the file it is told to obey.

## Three riskiest things

1. Rendered typing is still O(document) (`pmToMdast` per transaction). Under the 1.17 protocol the contended CI runners report 10k-word pane p95 20.6 / 22.7 ms; macos 1-worker CI is 11.9 ms; r1 isolated runs were 9.5–11.7 ms. Incremental conversion is on the backlog with a quiet-single-worker trigger. Phase 2 adds autosave and a watcher to the same path.

2. Every new reader of the store that is not an editing surface must flush. Copy, undo/redo, toggle and unmount now do; the markdown pane still lags a source burst by design (1.23 enumeration, G9). Phase 2 autosave is the next reader. The promoted rule names the test shape (an action inside the window); a save path that only tests after the window will miss G1 again.

3. The `&#x20;` family's mark-edge member remains reachable the moment a caret sits at the end of an existing emphasis/strong run with more text after it. 1.25 closed the line boundaries; the backlog trigger is the first mark-toggle or Rewrite edit inside a mark. Input rules already create those marks.

## Class-level lessons (for docs/lessons.md)

- LESSON: a procedure change written into `CLAUDE.md`/`AGENTS.md` by a verify task does not update the generated per-task `PROMPT.md` wrapper, so the next task in the same chain is handed steps that contradict the file it is told outranks task text → the generator copies the current `## Every iteration` list, or the promoting commit updates the template in the same tree; "stop and do not decide" is for substance conflicts, not a stale wrapper's step count (1.verify.r2.g1 attempts 1 and 2).
- LESSON: a corpus file can ship F9c's real collector (`checkedNames` / `blockEndChecked`) and still keep `names.length === Object.keys(index).length` where `names` is `Object.keys(index).sort()` → drop the tautology; the collector is the coverage claim.
- LESSON: Grok's r1 G1 nit against a blocker was a severity-vocabulary miss, not a visibility miss — `copyMarkdown` without `flush` was in the tree — and the template's new blocker example is that exact button → rate silent wrong output on a named gate control as blocker even when a lagging pane agrees with it.
