## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **should-fix — Required** — **packages/editor/src/toggle.ts:567**, also **:506** — A freshly closed emphasis or strong input rule leaves stored marks cleared, but toggling at the block's end puts the source caret inside the closing delimiter. Type `see *foo*`, then `X`: Copy yields `see *foo*X\n`. Repeat, inserting Ctrl+/ immediately before `X`: Copy yields `see *fooX*\n`. Strong behaves identically (`see **foo**X` versus `see **fooX**`). The dev readout proves the precondition in both runs: `before: "see foo"`, the relevant resolved mark, `stored: []`. `/report/marks-browser.mjs` and .log reproduce through real typing and clipboard access. `isLeafEnd` excludes text nodes, so the new stored-marks rule only moves the block-final inline-code caret; an ordinary mark's innermost text uses its spelling-table end before the delimiter regardless of stored marks. Headless guards also reproduce delete-mark and astral members; inline-code and mid-block controls agree. **Fix:** resolve the enclosing mark boundaries at a block end against the effective typed-mark set, placing the source caret outside each mark the next character will not inherit, including nested marks. Add both input-rule and inherited-mark routes for emphasis/strong, synthetic cleared-delete coverage, all textblock kinds and astral members; compare the two views' typed bytes in addition to the inverse. This is the cursor-placement severity of M4/M5/L6: the resulting documents remain fixed points, but a routine toggle changes the formatting of the next character.

2. **should-fix — Required** — **packages/editor/src/toggle.ts:172**, with **packages/editor/src/schema.ts:918** — Inline correspondences derive live ProseMirror positions from normalized mdast widths, so leading whitespace removed during conversion shifts subsequent retained characters. Load `a ` followed by code span `cd` and ` b`; click before the first `a`, Delete it, then click between `c` and `d`. The readout says `before: " c"` while the Markdown pane is `` `cd` b\n ``. Type `X` directly: `` `cXd` b\n ``. Toggle to source first and type `X`: `` `cdX` b\n ``. Strong gives `**cXd** b` versus `**cdX** b`. `/report/trim-browser.mjs` and .log reproduce both pairs with measured clicks and editor-state preconditions. `walkInline` starts the code/text correspondence at the block's content start although the live document still contains the leading space; `pos - inside.pmStart` is therefore one too large. The same error can satisfy `toRendered(toSource(p)) === p`, since both directions share the false start. This is not the accepted loss of trailing whitespace or a fenced-code interior. **Fix:** preserve a correspondence from normalized inline output to its actual live offsets through whitespace removal/collapse, and consume that correspondence in both cursor directions. Extend the destructive corpus leg to remove leading content before retained runs and assert character-relative placement or two-view insertion equivalence, not just total-width bounds and self-inversion. Include plain text, marked text, inline code, container prefixes and astral characters. Do not restore the serializer's forbidden whitespace or discard the user's live buffer to make the map agree.

## Three riskiest things

1. Normalization changes live offsets, yet both directions can share the same incorrect correspondence and pass the inverse. The destructive corpus leg's width-based bound cannot prove retained-character placement.
2. Effective stored marks and enclosing Markdown delimiters remain separate state. The code-span repair demonstrates one member; ordinary and nested marks need the same two-view oracle.
3. Phase 2 inherits explicit cursor and serializer exceptions: canonicalCursor's inline-code interior, fenced-code interiors, container hard-break ends and deferred HTML/autolink behavior. File-open and autosave are the recorded revisit points; source commit p95 is already 54.4 ms locally.

## Class-level lessons (for docs/lessons.md)

- LESSON: two inverse functions built from one incorrect offset table can agree perfectly while inserting at the wrong character → assert correspondence to surviving live characters and compare the two views after destructive normalization, alongside self-inversion.
- LESSON: a mark-end repair limited to the node type that exposed it misses other input rules with the same cleared stored-mark state → enumerate all mark families and both inherited/cleared routes, including the enclosing marks of an innermost text node.
