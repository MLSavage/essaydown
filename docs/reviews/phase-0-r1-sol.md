## Findings (≤ 20, most severe first)

1. **blocker** — ralph/lib/util.mjs:102 — Stale-lock recovery removes a live owner's lock before checking identity, allowing another entrant to execute concurrently with that owner. Reproduction: breaker B reads stale bytes; A recovers and enters its critical section; B renames A's lock away; C acquires the now-absent pathname and enters while A is still active; B then discovers the mismatch and aborts too late. `/report/lock-probe.mjs` uses a real child for A and a filesystem-call scheduling hook to run C after B's actual rename, without changing repository code. The existing test only checks B aborts and A's token is restored; it never attempts C in the exposed window. This is distinct from the deferred second-`ralph.sh run` issue: concurrent gate/admin/runner mutations are supposed to be serialized by this mutex. Fix: cut automatic stale-lock breaking to a documented manual recovery procedure performed only after all runner/gate/admin processes have stopped, as the project rules prefer; stale or empty locks must cause refusal rather than removal. Add a regression that asserts a live holder's path is never temporarily freed.

2. **blocker** — packages/core/src/sidecar.ts:757 — The scanner compares literal key spellings, so a quoted duplicate of an app-owned key bypasses the duplicate-key write prohibition. With front matter `question: Old?` followed by `"question": Other?`, `writeFrontMatter(root, {question: 'New?'})` returns `ok: true` and rewrites the first line; the duplicate remains. With only the quoted spelling, the same lookup treats the key as absent and can append a second spelling. PRD §6.1 and task 0.10 require duplicate/unsupported app-owned keys to return FrontMatterUnsupported and preserve the block. Evidence: the final case in `/report/core-probe.test.ts` fails; `/report/core-probe.log` contains the returned modified root. Fix: recognize equivalent app-owned key spellings during duplicate detection, or conservatively reject mappings containing unsupported quoted key syntax before any app-owned write. Test single-quoted, double-quoted and escaped spellings, both alone and paired with the plain spelling, and assert refusal preserves root identity and bytes.

3. **should-fix** — packages/core/src/sentences.ts:411 — Identity reorder and same-Markdown replacement reconstruct slices even when no change was requested, splitting marks spanning sentence boundaries. `**First sentence. Second sentence.**` reordered by `[0,1]` becomes `**First sentence.** **Second sentence.**`; replacing the first sentence of `[First sentence. Second sentence.](https://example.com)` with `sentenceMarkdown(paragraph, 0)` turns one link into two and removes the intervening space from the link. The replacement path is at sentences.ts:367. Both failures are recorded in `/report/core-probe.log`; the indexed corpus lacks these spanning-mark shapes, so its identity tests do not catch them. Fix: after input validation, preserve the original tree for an identity permutation and an unchanged sentence Markdown replacement; add spanning strong/link cases to the no-op regressions and corpus. Preserve tests for real replacements and reorderings, which still need slicing.

## Three riskiest things

1. Lock ownership is tested at acquisition and release, but mutation of the lock pathname exposes an intermediate state in which a second critical section is authorized.
2. Front-matter safety depends on a partial scanner distinguishing semantic key identity from spelling; a missed spelling authorizes a write into a block the contract makes read-only.
3. Corpus-wide tests cover only shapes represented by the corpus. Spanning marks remain outside the identity fixtures despite the promoted rule, and aggregate coverage does not expose that omission.

## Class-level lessons (for docs/lessons.md)

- LESSON: checking identity after a destructive lock operation detects the race after exclusivity has already been lost → test admission by a third actor at every intermediate state; prefer manual stale recovery when the available primitives cannot preserve exclusion.
- LESSON: duplicate detection on raw syntax misses equivalent key spellings → normalize the supported key grammar or refuse unsupported syntax before deciding a field is writable or absent.
- LESSON: rebuilding a document for an unchanged request can alter mark topology even when visible words stay the same → preserve validated no-op inputs and include marks spanning operation boundaries in identity fixtures.
