## Three riskiest things

1. **The serializer is an unowned half of the fixed-point property.** Every Phase 1 fix (F1, G3/G4, H1, H8, I1, I3/I4) landed in the editor's strip on the assumption that `format` is right about flanking. Finding 1 shows one GFM handler has no flanking logic at all, and `format.ts` is 100% covered without owning that handler. Tables, autolink literals and inline code were not walked the same way; nothing in the tree reads the handlers, so the next extension added reopens the question.

2. **The enumerations are as complete as their kind tables, and the property test that would replace them is still a Phase 2 planning line.** Finding 2 is a pair the 225-case enumeration cannot express; finding 1 is a neighbour class (punctuation) the mark-edge guards never varied. `[review-1-r2, Claude risk 1]` defers a sweep of arbitrary transactions to Phase 2, while the gate criterion it discharges is Phase 1's.

3. **Source commits retain a separate pending buffer.** Copy, undo/redo, toggle and unmount now flush, each with an inside-the-window case; the markdown pane still lags a source burst by design. Phase 2 autosave is the next reader. Source 10k commit p95 on the accepted runners is 75.0 / 72.3 / 91.6 ms (n=5 bursts) — the number autosave will wait on. Rendered typing is still O(document).

## Class-level lessons (for docs/lessons.md)

- LESSON: CommonMark §6.2's flanking rules read punctuation as well as whitespace, and only `mdast-util-to-markdown`'s own `emphasis`/`strong` handlers encode for them; an extension handler (`~~`) writes the delimiters blind, so an edit that puts punctuation inside a mark's edge next to a letter outside it produces bytes the parser cannot close → before assuming the editor's strip is the place to fix a mark-edge defect, read the serializer's handler for that mark for its flanking logic, and enumerate every mark-edge guard over both neighbour classes (whitespace, punctuation) on all three flanking marks.
- LESSON: an enumeration that mirrors a third-party rule (`join.js`, `prepareList`) is complete only when its kind table is derived from that rule's own branches (paragraph→paragraph, →definition, →setext heading), not from the mdast type list — a pair the table lacks is a pair the 225 cases cannot fail on.
- LESSON: a read-only review that treats "the family is closed because the last fix's guards are green" will miss the next member whose construction (a deletion of the unmarked neighbour, a punctuation edge) is outside those guards → walk the ownership rule against the CommonMark / GFM clauses it cites, including the neighbour classes the rule does not name, and treat a deferral's reachability claim as a hypothesis against the legs' own ranges (I1 at r3; finding 1 at r4; Grok's lane).
- LESSON: a caret-motion regex guard enumerates the modifier *chain* (`(?:[A-Za-z]+\+)+`), not the modifier names it has seen; the spelling the next spec uses is the one the alternation lacks.
- LESSON: a guard's allowlist states a reason that must be checked against the manifest and the source (a keymap from a package the lockfile does not contain is not the reason a press is safe); a false reason survives every green run and misleads the next repair's scope decision.
