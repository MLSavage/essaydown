## Findings (≤ 20, most severe first)

1. **blocker** — ralph/lib/run.mjs:104 — The lock protects task startup but is released before the iteration, allowing two runner processes to launch the same task concurrently in one worktree and overwrite the same transcript. `/report/runner-probes.mjs` starts a second invocation while the first fake iteration sleeps; both report `0.1 attempt 1` and two child PIDs enter the iteration. Fix: apply the PRD §12 fallback now—one manually supervised sequential stream and manual integration, recorded by the principal in DECISIONS; repair execution ownership in the separate runner work before Phase 1, with a two-process regression proving the second invocation cannot start work. Do not add another orchestration layer in this phase.

2. **blocker** — packages/core/src/sentences.ts:168 — Offset slicing drops zero-width images at the end of a paragraph; an identity reorder of `Hi. ![](x.png)` produces `Hi.&#x20;\n`, deleting the image, and a linked empty-alt image is also deleted. `/report/probes.log` reproduces both through exported functions. The mark branch's `hi <= lo` check at line 185 independently discards zero-width descendants. Fix: give zero-width inline nodes explicit ownership at slice endpoints, traverse wrappers containing them, and test identity reorder and replacement with leading/trailing, adjacent, and linked empty-alt images; assert node presence and URL preservation as well as text.

3. **blocker** — packages/core/src/sidecar.ts:820 — The front-matter scanner treats malformed scalars as writable and misdecodes valid quoted values: `title: bad: mapping` and `title: "\q"` are writable, while `title: "\u0041"` is mirrored as `u0041` instead of `A`. `/report/probes.log` shows successful writes into the malformed blocks, contrary to the required FrontMatterUnsupported boundary. Fix: validate the supported scalar grammar, decode YAML escapes correctly, reject unknown escapes and invalid plain-scalar colon syntax, and return FrontMatterUnsupported without changing the root for malformed input. Add valid-escape, invalid-escape, and malformed-value regression cases; obtain approval before introducing any dependency.

4. **should-fix** — packages/core/src/parse.ts:52 — Parsing does not normalize CRLF within node values despite its contract and task 0.6's normalization requirement. `parse('first\r\nsecond\r\n')` retains CRLF in its text node; a two-line fenced code value does likewise, and formatting emits mixed line endings. The corpus's CRLF fixture puts breaks between blocks, where the parser naturally consumes them, so the existing assertion cannot catch this. Fix: normalize non-opaque text/code line endings while retaining the specified opaque byte fidelity, and extend the CRLF fixture/tests to multiline paragraphs and fences, with separate html/yaml preservation cases.

5. **should-fix** — packages/core/src/sidecar.ts:926 — A newline supplied while editing a single-quoted title is emitted literally inside the quotes and writeFrontMatter reports success, creating a multiline value outside its own supported boundary. `/report/probes.log`: editing `'Old'` to `Line one\nLine two` writes two physical scalar lines. Fix: reject unsupported multiline replacement values with FrontMatterUnsupported before any edit, preserving root identity and other bytes; test LF/CR and all quoting styles.

6. **should-fix** — ralph/lib/run.mjs:235 — Review startup trusts runtime integrated_sha without consuming the verifier's accepted.json or checking artifact digests. In the disposable runner probe, replacing the accepted artifact contents after the gate still launches all fake reviewers and advances to reconciliation. The existing digest-rejection conformance test exercises the helper, not this consumer. Fix: invoke readAcceptedCi for the dependency gate before recording review metadata, require its SHA to equal both verification and implementation SHAs, and reject missing/tampered artifacts through the actual run command. Until repaired, make this a mandatory manual pre-review check.

7. **should-fix** — docker/compose.yml:79 — Each reviewer can read every other reviewer's directory through both the whole-repository bind and `/logs`, contrary to RUNNER-SPEC §5.2's isolation requirement. Read-only access prevents alteration but does not prevent contamination. Fix: expose only permitted evidence plus attempt metadata and the reviewer's own report path, and mask peer reports at every mounted alias, including the host-path checkout; verify denied access with sentinel files, not real peer reports. The same change is needed for all three reviewer services.

8. **should-fix** — .github/workflows/ci.yml:145 — All three matrix artifacts contain the same `lint.log`, `test.log`, and `cargo-test.log` paths, and merging without OS directories overwrites the files; the accepted verifier artifact contains only three files instead of three identifiable OS sets. Consequently the digest-verified artifact cannot substantiate all three OS runs; only the unmanifested workflow.log retains them. Fix: place each OS's logs under a unique directory before uploading/merging and assert all three directories are present in the accepted artifact.

9. **should-fix** — packages/core/src/blocks.ts:166 — Every block mutation deep-clones the entire root, so the real editing operations provide none of the structural sharing required for the 500-snapshot undo stack; sentences.ts:295 does the same. The undo tests instead supply manually shared trees, and undo.ts:19 incorrectly claims 500 snapshots cost only 500 roots. Fix: copy only the changed ancestor paths/child arrays and preserve unaffected subtree identities; add an integration assertion that a real replace/move followed by push retains the untouched subtree by identity, then correct the memory claim.

10. **should-fix** — packages/core/test/sidecar.test.ts:979 — `pnpm --filter @essaydown/core typecheck` fails TS2339 because `entry.variants` is read from an unnarrowed union. `/report/typecheck.log` reproduces the error at the reviewed SHA; the green lint/test gate does not typecheck it. Fix: narrow the orphan's `list` discriminant before accessing `entry.variants`, and run this existing typecheck command in validation so compilation errors cannot remain behind passing runtime tests.

11. **should-fix** — ralph/lib/util.mjs:44 — writeAtomic is documented as fsynced but only writes, closes, and renames; it never calls fsync, including when writing the close intent required to be durable before the Git ref transaction (RUNNER-SPEC §8.4). A process-exit injection does not test power-loss durability. Fix: fsync the temporary file before rename and persist the containing directory after rename using supported host semantics, or explicitly cut automated close to the prescribed manual procedure until durability is implemented and reviewed.

## Three riskiest things

1. Concurrent runner invocations share a task worktree and transcript; green CAS and crash tests do not establish exclusive execution.
2. Supported editing operations silently remove non-text content, while the A/B/C corpus tests only parse/format trips.
3. Front-matter read/write claims exceed the scanner's grammar, permitting malformed writes and incorrect sidecar values.

## Class-level lessons (for docs/lessons.md)

- LESSON: Branch coverage and a fixed corpus miss combinations of supported syntax → test identity edits containing zero-width nodes, wrappers, and endpoint whitespace, and assert structure as well as prose.
- LESSON: CRLF tests containing only block separators never exercise node-value normalization → place line breaks inside paragraphs and code and separately pin opaque-byte behavior.
- LESSON: A permissive hand-written scalar scanner can silently corrupt values while claiming to reject malformed input → define and validate the accepted grammar, with invalid-neighbor cases and escape round trips.
- LESSON: Lock-unit tests and single-process transactions do not prove exclusive task execution → exercise two live runner processes against one worktree before enabling unattended execution.
- LESSON: A tested digest helper does not protect a consumer that never calls it → tamper evidence through each real entry point and require refusal before work starts.
- LESSON: Read-only evidence mounts protect integrity but not reviewer independence → test denied cross-reviewer reads through every filesystem alias.
- LESSON: Synthetic sharing tests prove that an undo container retains references, not that edits share memory → assert sharing across actual mutation-plus-history operations.
