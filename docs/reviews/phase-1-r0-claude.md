## Findings (12, most severe first)

1. **blocker** — `packages/editor/src/schema.ts:529` (with `packages/core/src/format.ts:71`) — a paragraph edited in the rendered view keeps ProseMirror's text verbatim, so an ordinary trailing space becomes the HTML entity `&#x20;` in the file the user copies or saves. `pmToMdast` returns `{ type: "text", value: node.text }` with no whitespace normalisation, and `remark-stringify` escapes the resulting boundary space. Reproduced end to end on `/dev/editor` at this SHA: `hello ` + Enter + `world` → `"hello&#x20;\n\nworld\n"`; `a sentence ` → `"a sentence&#x20;\n"`; `- one ` + Enter + `two ` → `"- one&#x20;\n- two&#x20;\n"`. `parse()` **already** discards these spaces (`format(parse("hello \nworld\n"))` → `"hello\nworld\n"`), so the two entry points into the store disagree and the editor can produce a root no Markdown file parses to. This is what Michael reported at the gate and escalated (`/logs/human/1.9/a2.md`); DECISIONS #repair-1.9 leaves the disposition to this reconciliation. Nothing in the suite can see it: every leg of the round-trip corpus is seeded from `parse(fixture)` (`packages/editor/test/schema-roundtrip.test.ts:19-25,50-53`, `packages/core/test/roundtrip.test.ts`), and the parser has already normalised the whitespace away before the assertion begins. Fix: make `pmToMdast` agree with `parse` — drop whitespace at a text run that is first or last in its block (leave a run adjacent to a `break` node alone, which already serialises correctly as `"hello \\\n"`), and add one corpus leg seeded from a ProseMirror doc built by typing rather than from `parse`, so the class cannot come back. *(Note for the reconciliation: rated blocker because it falsifies the gate row's own human criterion on the gate owner's evidence and no test guards it. If the reconciliation prefers `should-fix` + required, the fix task is the same; what it must not do is defer it, because Phase 2 puts this string on disk.)*

## Three riskiest things

1. **The invariant corpus can only see trees the parser produces.** Every leg of A/B/C, of the 1.1 ProseMirror round trip and of the 1.2 position map starts from `parse(fixture)` — so no test in 1524 can reach a root that only the editor can build. `&#x20;` (F1) is one instance that a human found in an hour of typing; the same blind spot covers every editing path Phase 3 adds (`replaceSentence` from a Rewrite card, `moveBlock` from a Reorder drop, an Outline question edit), and each of those writes to disk. The corpus needs at least one leg seeded from the editor's own output before Phase 3 starts, not after it.

2. **Both editing paths are O(document) per keystroke and nothing in the suite measures them.** Rendered typing runs `pmToMdast` + `format` over the whole document and clears 16 ms only up to ~12k words (F7); source typing runs `parse` over the whole buffer and is already at 41 ms p95 at 10k words (F2). There is no latency assertion anywhere in the repo, so the only reason anyone knows these numbers is that a review-set description happened to name one of them. Phase 2 adds autosave and a watcher to the same path and Phase 3 adds three sidebars; the first phase whose gate is a real user typing for an hour is Phase 6.

3. **`Mod-` is a module-level platform constant in both keymap libraries, and only half of it is now tested.** The `1.verifyh` failure was one instance; after 1.11 the ProseMirror half has 26 platform-parameterised tests and the CodeMirror half still has name-string assertions (F5), while the e2e presses a shifted-chord spelling no keyboard produces (F6, proved by a mutation that deleted `Mod-Z` and changed no test result). The gate is green on three real operating systems, which is strong evidence — but it is green partly because these assertions cannot fail, and that is not the same thing.

## Class-level lessons (for docs/lessons.md)

- LESSON: a round-trip or invariant corpus seeded only from `parse(fixture)` is closed under the parser, so a defect the editor introduces on the way *out* is unreachable by construction and no coverage number will say so → every round-trip family gets one leg seeded from the writing surface's own output (a ProseMirror doc built by typing, a mode operation's result), and the corpus test names which leg is which.
- LESSON: a keymap assertion that reads the binding table (`b.key === "Mod-Z"`, `binding.run(view)` called directly) or an e2e that spells a shifted chord as `Shift+<lowercase>` asserts the registration, not the dispatch, and passes identically on the platform where the chord is dead → every chord gets one test that dispatches the event a real keyboard emits, on each platform the library's module-level `Mod-` constant can resolve to, and a mutation check (delete the binding; the test must go red) before the task is called done.
- LESSON: a deferred finding whose revisit trigger is "the first task that calls X" survives only if something looks — H2 named `writeFrontMatter` and task 1.8 called it without anyone noticing → a deferral that names a code trigger also names the mechanical check (a grep, a phase-verifier checklist line) that fires it, or it is not a deferral, it is a wish.
- LESSON: measuring the route rather than the function is what located the cost — at 10k words `parse` is 37 ms and `format` is 0.89 ms, the opposite of what the module names suggest → the phase that introduces a per-keystroke path measures it end to end on the route in that phase and commits the budget as a test, rather than leaving the first measurement to a reviewer two gates later.
- LESSON: a hand-written record that is byte-shaped like a tool-written one erases its own provenance, and the fix is a line in the file, not a feature in the tool → any evidence file produced by hand carries a `provenance:` line naming who wrote it and from what.
