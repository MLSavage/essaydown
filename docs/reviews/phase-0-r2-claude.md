## Findings (≤ 20, most severe first)

1. **should-fix** — `ralph/lib/util.mjs:132` (with `:174` and `ralph/lib/doctor.mjs:57`) — a lock file whose first field is not a positive integer is folded into "holder is dead": `const known = Number.isInteger(pid) && pid > 0; … alive: known && pidAlive(pid)` makes `alive` false for an unidentifiable holder, so `withLock` throws *"is held by pid unknown, **which is not running**"* and `doctor` prints `stale-lock unknown (<path>) → …remove <path> by hand` — while `lockHolder`'s own doc comment says such a lock "counts as held by something we cannot identify — fail closed, because inventing a holder is how a live lock gets broken". The empty-file case is reachable inside `withLock` itself: between `openSync(lock, "wx")` (`:167`) and `writeSync(fd, mine)` (`:169`) the lock exists and is zero bytes, so a contender that lands in that window is told a lock a live process created microseconds earlier is stale. Probe: writing `""` or `"not-a-pid junk\n"` to the lock reproduces both the message and `alive:false`. Nothing is broken (the refusal is still fail-closed, and the repair text's `pgrep` step would stop an operator), but it is a false stop with a destructive instruction attached. Fix: give the case its own branch — `lockHolder` returns `pid: null, alive: true` (unidentifiable ⇒ assume live), `withLock` falls into the poll/timeout path and throws `lock <file> held by an unidentifiable holder` at `timeoutMs`, and `doctor` reports `unreadable-lock (<path>)` with a repair that does not assert the holder is gone; add the leg to `ralph/test/util.test.mjs` beside the dead-pid one.
2. **should-fix** — `packages/core/src/sidecar.ts:1104` — `needsQuoting`'s contract is "whether a plain scalar would be re-read as something other than this exact string", but it tests only emptiness, surrounding whitespace, `isUnwritableRaw`, ` #` and `: `, and the leading indicator — never YAML's implicit type resolution. Probe: writing the *strings* `true`, `false`, `null`, `~`, `yes`, `no`, `on`, `off`, `123`, `1.5`, `0x10`, `.inf`, `NaN`, `2026-01-01` into `title:`/`question:` emits them bare (`question: true`), which the app's own hand-written reader takes back as the string but any real YAML reader — Typora, Obsidian, and pandoc `--standalone` in Phase 4 — takes back as a boolean/number/date. Invariant A and the in-app round trip both hold, so this does not touch the gate criterion; the loss is the cross-tool promise of PRD §2 ("open the same `.md` in Typora, Obsidian, or `cat`"), and it is the same class as G2 — the writer's boundary is not the boundary of the format it writes. Whether it is *required* is the reconciliation's call. Fix: add the YAML 1.1/core-schema implicit resolvers (`true|false|yes|no|on|off|null|~|` empty `|` integer `|` float `|` `.inf`/`.nan` `|` ISO date/timestamp, case-insensitive) as one more clause of `needsQuoting`, so such values are promoted to a quoted scalar; extend the `readable(v) === !needsQuoting(v)` value table in `front-matter-boundary.test.ts:231` with them.

## Three riskiest things

1. **`cargo test` is still 0/0/0 on every OS.** The Rust half of the product — `WorkspaceRoot`, the watcher, the sidecar spawn, `trash`, `keyring` — has no test of any kind, and the three-OS green that the phase gate rests on is, for Rust, only "it compiles". Every path-contract requirement of PRD §6.4 (canonicalisation, traversal, symlink, junction, case-fold, `ErrorKind` assertions) is deferred wholesale to Phase 2, which is also the first phase whose gate is a WebdriverIO run rather than a unit suite. If the `WorkspaceRoot` contract turns out to need a different shape, it lands in the phase with the least slack. r1 recorded this as G13; it is still the largest untested surface in the tree.
2. **The lock's liveness test is `process.kill(pid, 0)` on a pid read from a file on a bind-mounted volume.** Nothing records *which* pid namespace wrote it. PRD §9.10 confines lock-taking to the host, so this is safe as specified, but the repo root — and therefore `.locks/` — is mounted into every container at both `/work` and its host path, and the failure is silent in both directions: a host pid checked inside a container usually looks dead (finding 1's refusal, now with a manual-removal instruction), a container pid checked on the host often collides with a live system process (a 30-second wait then a wrong "held by pid N"). The mitigation is a convention, not a check. Consider writing a namespace/boot-id discriminator into the lock line and refusing to judge liveness across it.
3. **The corpus is the only oracle, and it only knows the shapes someone thought to add.** G3 existed because no indexed fixture carried a mark across a sentence boundary; 0.24 closed that by adding six fixtures — which is the right fix and also the demonstration that a corpus-driven invariant can only be as complete as the corpus. The same argument now applies to what is *still* absent: no fixture combines front matter with a spanning mark, none carries a `break` inside a sentence, none has an `html` node inside a list item, and none exercises `moveSection` on a document whose first heading is deeper than its second (the moved golden itself produces such a document, and nothing round-trips it back). Property-based generation over the §6.1 node set, even a small amount of it, would find the next G3 before a reviewer does.

## Class-level lessons (for docs/lessons.md)

- LESSON: a predicate that reports "the holder is dead" for two different states — a pid we checked and a holder we could not identify — turns an unreadable file into a destructive recommendation → give "cannot identify the holder" its own branch and let it fail into the wait/timeout path, never into the recovery path.
- LESSON: when a fix replaces a mechanism the spec names by a different mechanism with different failure semantics, amending only the *behaviour* sentence leaves the wrong mechanism spelled one clause earlier → the commit that changes a recovery model also renames the primitive wherever the spec and DECISIONS name it, and strikes any earlier "same semantics" claim.
- LESSON: a test that derives a coverage claim from a metadata file asserts a property of the metadata → build the claim from the artefacts themselves and assert the metadata against them separately, so the index cannot certify itself.
- LESSON: a rule promoted as "every operation of shape X" is discharged only for the operations the promoting task happened to touch → the promoting task enumerates the members of X from the module's exports in its journal entry, and the reviewer checks that list against the tree rather than against the rule's parenthetical examples.
- LESSON: a hand-written writer for a format the project deliberately has no library for is correct exactly against its own reader, and silently wrong against every other reader of that format → when a value must survive a third-party parser, the quoting predicate is derived from that format's spec (here, YAML's implicit type resolution), not from what the project's own reader accepts.
