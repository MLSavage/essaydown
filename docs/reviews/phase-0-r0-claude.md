## Findings (≤ 20, most severe first)

1. **blocker** — `packages/core/src/sentences.ts:169` — `sliceInline` assigns a zero-width atomic node (an image with empty alt, `![](path.png)`) to no slice when it sits at the end of a paragraph, so `replaceSentence` and `reorderSentences` silently delete it; `reorderSentences` loses it even under the identity permutation, contradicting the function's own contract ("a paragraph reordered by the identity permutation is unchanged", :344). Probe: `One. Two. ![](i.png)` → `replaceSentence(id, 0, "X.")` yields `X. Two.&#x20;` and `reorderSentences(id, [0,1])` yields `One. Two.&#x20;` — the image is gone from the document. Reachable from Phase 3's Rewrite "Use this" and every Reorder drop, i.e. silent loss of the user's content. Fix: give `sliceInline` an explicit `includeAtTo` parameter, change the atomic test to `start >= from && (start < to || (includeAtTo && start === to))`, and pass `includeAtTo: true` only from the final slice that reaches `plain.length` (`sentences.ts:329` in `replaceSentence`, and the final `gapNodes` call in `reorderSentences` at :383). Add a corpus-level regression asserting `parse(format(reorderSentences(root, id, identity)))` deep-equals `parse(format(root))` for every top-level paragraph of `essay-fixture.md`.
2. **blocker** — `packages/core/src/sentences.ts:169` — the same condition's `zeroWidth && start === from` clause makes a zero-width atomic node at offset 0 match **both** `sliceInline(children, 0, previousEnd)` and `gapNodes(children, previousEnd, sentence.start)` when `index === 0` (both ranges are `(0, 0)`), so it is emitted twice. Probe: `![](i.png) One. Two.` → `replaceSentence(id, 0, "X.")` yields `![](i.png)![](i.png) X. Two.` — the image is duplicated in the saved Markdown. Same root cause and same fix as finding 1: removing the `zeroWidth && start === from` special case in favour of an explicit `includeAtTo` flag eliminates the double emission, because `0 < 0` is false for the leading slice.

6. **should-fix** — `ralph/lib/util.mjs:97` — `withLock`'s stale-lock reclamation is a TOCTOU: the liveness check (`readFileSync` + `process.kill(pid, 0)`) and the `unlinkSync(lock)` are not atomic with respect to the lock file's identity. If process A breaks a stale lock and acquires it while process B is between its own `process.kill` check and its `unlinkSync`, B deletes **A's live lock** and then creates its own, so both hold "the" lock at once. This is exactly the crash-recovery path the runner is designed to exercise (a stale lock exists only after a crash), and `scripts/gate.sh` on the host can genuinely run concurrently with `ralph.sh run`. The `finally` unlink at :102 has the same flaw in reverse: it unlinks unconditionally, even a lock it no longer owns. Both violate CLAUDE.md's "one lock". Fix: make breaking and taking the lock one operation — `renameSync(lock, lock + "." + process.pid + ".stale")` and continue only if the rename succeeded (rename of a path another process already replaced fails or moves the wrong file, so also write a random token into the lock, re-read it after acquisition, and abort if it is not yours); on release, read the token back before unlinking.

## Three riskiest things

1. **`sliceInline`'s slice-assignment rule is off-by-one at both ends of the paragraph, and the test suite cannot see it.** Findings 1 and 2 are silent corruption — content deleted or duplicated — in the module every Phase 3 mode will call. They survived 91 sentence tests and 30 conformance cases because every one of those cases is prose with no zero-width atomic node at a paragraph boundary, and because the corpus invariants A/B/C only ever exercise `parse`/`format`, never `replaceSentence`/`reorderSentences`. The class of gap is that the mutating APIs have no round-trip invariant of their own: nothing asserts "identity operation ⇒ identical document" over the corpus, which is the single cheapest test that would have caught both.
2. **The runner is the least-verified code in the repository and the most load-bearing.** It moves refs, is the sole author of `main`, and is exempt from lint, typecheck, the vitest run and CI (finding 4). Its conformance suite is excellent — 61 tests covering CAS, crash injection at every ref-move boundary, gate rewiring and close idempotence — but it is run once at bootstrap and never again, while three `fix(runner):` commits landed on `phase/0` after that point. Combined with the `withLock` TOCTOU (finding 6), a runner regression can reach `main` with nothing in the gate objecting.
3. **The gate's digested evidence proves less than the gate claims.** The accepted artifact for 0.verify.g1h contains one OS's logs, not three (finding 5), and the file that does carry the three-OS proof — `workflow.log` — is outside `artifactNames` and therefore outside the digest chain that RUNNER-SPEC §12 makes every consumer verify. Today the claim is true (I read all three runners' `431 passed` out of `workflow.log`), but the mechanism that is supposed to make it *checkable* does not cover it, and the same defect is already latent in every later phase's CI gate, including the Phase 6 final-package gate whose digests the manual publication procedure compares against.

## Class-level lessons (for docs/lessons.md)

- LESSON: a pure-function API that returns a modified copy was tested only on inputs that change, so its identity case (`reorder` by the identity permutation, `replace` with the same text) was never asserted → for every `f(doc, args) -> doc` in `packages/core`, add one corpus-wide test that the no-op argument returns a document that re-serializes byte-identically; it is one assertion and it catches boundary-assignment bugs that curated prose cases cannot.
- LESSON: offset-range code that partitions a string into adjacent half-open slices silently mishandles zero-width items, because a zero-width item at a boundary satisfies "belongs to both" or "belongs to neither" depending on which inequality is written → when slicing a sequence by offsets, decide the ownership rule for width-0 elements once, write it in the doc comment, and test the first, middle and last positions explicitly.
- LESSON: `pnpm lint && pnpm test && cargo test` was treated as "the green bar", so anything outside those three commands (`tsc --noEmit`, `pnpm coverage`, `ralph/test/run.sh`) drifted unchecked while every task honestly reported green → the green bar must be the union of every check the phase's acceptance relies on; if a check is worth writing, wire it into the bar and into `ci.yml` in the same task that writes it.
- LESSON: an eslint `ignores` entry (`ralph/**`) added for convenience removed the project's own orchestration code from every static check for the whole phase → treat a lint-ignore of a source directory as a scope decision needing a DECISIONS note, not a config detail.
- LESSON: CI evidence was accepted on the strength of the *run's* conclusion while the *artifact* that gets digested and archived held only one matrix leg → when a gate's acceptance names N environments, assert that the accepted artifact contains N distinguishable records, not merely that the run succeeded.
- LESSON: `openSync(path, "wx")` gives a correct mutex, but the stale-lock recovery bolted onto it (read pid → check liveness → unlink) reintroduced the race the primitive removed → never break a lock by path; break it by identity (rename, or a token written into the lock and re-read after acquisition).
