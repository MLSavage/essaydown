## Three riskiest things

1. F14, still deferred (`docs/V1.1-BACKLOG.md`): `withLock` is released before the iteration (`ralph/lib/run.mjs:101` then the loop body). The lock's contract is state and ref mutation; a second operator-started `ralph.sh run` can still enter the same worktree. Manual procedure in DECISIONS #review-0-r0 stands. 0.25 closed the stale-break race; it did not take this.

2. Phase 1's save path, if it always calls `writeFrontMatter` for both app-owned keys, will `FrontMatterUnsupported` a document whose `title` or `question` is a quoted key spelling (G1, intended). The returned `root` is identity, so a caller that persists `write.root` is safe; a caller that treats `ok: false` as abort of the whole save is not. Skip keys whose `readFrontMatter` entry is not writable.

3. `cargo test` is still 0/0/0 on all three OS (G13). Phase 2 is the first real Rust evidence. A regressing `lib.rs` that still compiles will look green. `App.tsx:12` still `invoke("greet")` (G10, backlog); no Phase 0 acceptance clicks it.

## Class-level lessons (for docs/lessons.md)

- LESSON: a parameterized test that treats "refused" and "escaped" as equally green does not pin the quoting path the writer ships → assert `ok: true` (or `ok: false`) per code point from the production predicate, not from the acceptance's either/or.
- LESSON: after a check that two SHAs are equal, a second `if (acc.sha !== other)` against the other SHA is the same predicate; a conformance leg that flips `accepted.json.sha` exercises both at once and does not need a fourth fixture.
- LESSON: YAML merge-key verification inside a container with no `docker` binary is a hand-resolve of `<<:` plus explicit-key override, recorded as such; claiming `docker compose config` ran is the dishonest alternative.
