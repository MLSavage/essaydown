## Findings (≤ 20, most severe first)

Severity, rated by the consequence for the gate's criterion and never by the size of the fix (DECISIONS #review-1-r1): **blocker** — a gate criterion is not met, or wrong output reaches the user silently (example: Copy Markdown puts stale text on the clipboard and reports "Copied"); **should-fix** — a defect or a missing guard the phase should not close with, while the criterion still holds or the path is not the gate's own instrument (example: a redo chord bound under two names with no test that reads the binding table, so deleting one name stays green); **nit** — wording, citations, style, or an assertion with no behaviour behind it (example: `expect(checked).toBe(Object.keys(index).length)` where both sides are the same list). Mark a should-fix **Required** when the reconciliation should fail without it.

1. **blocker** — `apps/desktop/src/App.tsx:99`, `apps/desktop/src/workspace/document-sync.ts:225` — Switching files discards unsaved text when `flush()` encounters a conflict or an I/O failure. `flush()` resolves with `dirty === true`; App unconditionally replaces the pane and clears the error. Native reproduction: type `LOCAL` into `Alpha.`, externally write `EXTERNAL.`, wait for the conflict banner, click b.md and then a.md. Before: `Alpha.LOCAL`; after and disk: `EXTERNAL.` (`/report/native-probes-final.log:5`). The failure variant is independently confirmed by `/report/sync-probes.log:2`: a disk-full write yields a resolved flush with dirty state. Folder switching and rename also assume resolved means saved. Fix: return an explicit saved/blocked/failed result (or reject unsuccessful flushes), retain the current store and error until resolution, and prevent navigation/rename while unsaved; guard every caller with conflict and write-failure cases.

2. **blocker** — `apps/desktop/src/workspace/DocumentPane.tsx:162`, `apps/desktop/src-tauri/src/lib.rs:71` — The application has no close-request save barrier, leaving final edits only in the 500 ms timer when the process closes. Native typing followed by the suite's real process-relaunch route reads editor `EXTERNAL.XUNSAVED` but disk `EXTERNAL.X\n` (`/report/native-probes-final.log:8`). This probe establishes loss on process restart; source inspection establishes that normal window closure also has no flush/dirty guard. Fix: intercept normal close/quit, await completion of pending saves, and keep the window open on conflict/failure with a deliberate discard choice. Add an actual native window-close test inside the debounce, beside the restart guard; an unmount cleanup alone cannot reliably await shutdown I/O.

3. **blocker** — `apps/desktop/src-tauri/src/workspace.rs:356` — Renaming a document globally replaces the asset prefix in prose, code and opaque YAML, rather than only its relative image destinations. The direct probe compiles the unchanged workspace module: `a.md → b.md` changes both YAML `ref: assets/a/x.png` and literal code `` `assets/a/x.png` `` to `assets/b/x.png` (`/report/workspace-probes.log:1`). This silently changes authored content and violates opaque-byte fidelity. Fix: rewrite only syntactically identified image destinations referring to the moved assets, preserving all other source slices byte-for-byte; cover ordinary/escaped/reference image destinations plus prose, inline/fenced code, HTML and YAML containing identical bytes.

4. **blocker** — `apps/desktop/src/workspace/DocumentPane.tsx:124`, `apps/desktop/src-tauri/src/watch.rs:67` — An externally updated sidecar is silently replaced by the stale in-memory sidecar on the next Markdown edit. The watcher filters out `.essaydown.json`, the save checks only Markdown, and reload also reuses the old sidecar. Native probe opens a.md without a sidecar, writes a valid sidecar with `title: "Synced title"` and `topicQuestion: "Synced question"`, then types X. The saved sidecar has both fields null (`/report/native-probes-final.log:7`). Fix: track the sidecar's disk version with the document, reload/attach externally changed metadata when safe, and surface a conflict before overwriting changed metadata. Include sidecar-only external writes and initially absent sidecars in the guard set.

5. **blocker** — `apps/desktop/src-tauri/src/workspace.rs:353` — Rename's rollback stops before the final read/rewrite, so a failure there returns an error after moving the document and companions. The unchanged-module Rust probe renames a `.md` containing invalid UTF-8: result `Err(Io(InvalidData))`, but `old_exists=false new_exists=true` (`/report/workspace-probes.log:2–3`). The file tree lists such a file even though opening it fails, so the rename command remains reachable. A rewrite-write failure takes the same unrolled-back path. Fix: validate/read and prepare rewritten content before moving anything; include final rewrite failure in the transaction rollback, preserving original bytes and all three names. Test both read failure and a failed final write, not only assets-move failure.

6. **should-fix** — `apps/desktop/src/App.tsx:140`, `apps/desktop/src/workspace/DocumentPane.tsx:156` — The file tree never reacts to external creation/deletion/rename or placeholder download. Its refresh runs only for app-originated operations; the only event subscriber ignores every path except the open document. Native probe creates `external.md` while the folder is open and waits 1.5 seconds: disk has the file, tree does not (`/report/native-probes-final.log:6`). Fix: subscribe at workspace level and debounce a tree refresh for relevant directory changes, preserving selection and updating cloud-only entries; test externally added/removed files and a placeholder becoming downloaded.

7. **should-fix** — `apps/desktop/src/workspace/image-paste.ts:60` — Paste/drop detaches `insertImages()` without a rejection handler, so a rejected `file.arrayBuffer()` or `save_image` becomes an unhandled rejection and no actionable save error reaches the user. Both handlers share this path (`:68`); existing image tests cover successful storage only. This is a source-confirmed error-path gap; the accepted happy-path robustness log remains clean.

8. **should-fix** — `e2e/shell/test/robustness.spec.ts:15` — The task's ten-minute robustness session was replaced with six rounds to fit a single 60-second test, without a recorded task amendment. ## Three riskiest things

1. Save ownership across navigation, close, conflict resolution and outstanding I/O. The native probes show discarded buffers; the delayed-I/O probe also allows reload to finish before an earlier write lands (`/report/sync-probes.log:3`: reload `external`, final disk `mine`, dirty false). Serialize lifecycle operations and test controlled I/O completion orders before expanding this controller.
2. Rename combines three filesystem moves with source rewriting, while tests mostly exercise the happy path and one move failure. Literal-byte corruption and post-move failure are reproduced; the live editor also retains its old store until a watcher reload, leaving rename/edit timing dependent on event delivery.
3. Sync operates on Markdown alone, although metadata and the tree are independently changing parts of the workspace. Sidecar overwrite and stale tree are reproduced. The short robustness loop and excluded shell coverage do not establish safety for long sessions or delayed/error responses.

## Class-level lessons (for docs/lessons.md)

- LESSON: An awaited save function can resolve without saving → give callers a checked outcome, and test navigation/close during conflicts and failures rather than only waiting past a debounce.
- LESSON: An atomic write of one file does not protect a document's companion metadata → track and reconcile every independently writable member before replacing it.
- LESSON: Filename-driven global replacement cannot distinguish image URLs from authored literals → identify the intended syntax and preserve unrelated source slices, including opaque nodes.
- LESSON: A rollback test at one intermediate move does not cover a multi-step transaction → enumerate every fallible step after the first mutation and assert names and bytes after each failure.
- LESSON: A fixed timeout on each test is mistaken for a duration limit on the entire session → compose bounded tests and measure the requested total exposure instead of shortening it silently.
