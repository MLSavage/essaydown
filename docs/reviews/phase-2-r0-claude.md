## Three riskiest things

1. The user's own text is lost at the edges of autosave, and the suite tests only the happy transitions: switching files in conflict or after a failed save (1), quitting inside the debounce (3), renaming an open document with images (4), a flush racing an in-flight save (15). Michael's human gate never reached the conflict banner by hand (a1.md), so no one has exercised these paths on a real folder.
2. The sync-tool claims rest on synthetic fixtures: the `.icloud` spelling iCloud does not use on current macOS (11), a `.stfolder` whose assertion passes with the feature removed (2), a 14-second "10-minute" session with no backend log (2), and Windows e2e on the embedded provider, which proves DOM → store → disk but no native input (2.12's own statement). Phase 3 builds modes on this layer.
3. The `asset:` scope accumulates every folder ever opened and persists it, and `open_folder` accepts any path from the webview (5). The first script-injection defect in a later phase (html nodes, Coach output rendering) becomes a whole-disk read.

## Class-level lessons (for docs/lessons.md)
